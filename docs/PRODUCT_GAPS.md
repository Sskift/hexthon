# 产品差距与可借鉴方案

项目状态更新：2026-11-03，Hexthon v0.4.1。`npm start` 仍为无画面采集的接口模式；`Start-Hexthon.vbs` 或 `npm run start:assist` 使用小区域识别与场景浮层，并记住暂停状态。原生装备方案默认关闭，显式导入或开启自动同步后才写入。下文竞品资料核查截至 2026-11-02，其能力来自官网、帮助中心或发布说明，未在本机腾讯国服逐项验证；“未核实”不表示对方一定没有。商业产品未公开采集实现时，不推测它使用了截图、进程内存或某个 SDK。

本轮完善低分辨率识别、推荐解释、选人替换比较、生产控制器异常回放和手动便携更新。358 项本地测试通过，API、replay、lifecycle、面板 6 个场景及商店 7 个尺寸已通过；真实 Node 子进程覆盖 4 种更新成功／失败情形，官方 Electron 源码暂停启动的健康检查和退出也已验证。当前最终包、远端 CI 与正式 Release 尚待收尾，完整结果见 [0.4.1 发布记录](RELEASE_0.4.1.md)。旧 [0.4.0](RELEASE_0.4.0.md) 和 [0.3.1](PREFLIGHT_0.3.1.md) 保留为历史记录。

## 当前已接入的能力

- 三卡路径使用指定前台游戏窗口的按钮条带与标题条，有限重读未识别标题；精确识别并取得两次独立画面后才显示卡片附近的推荐。过期画面、窗口变化和不完整名称不作为新证据。
- 商店路径优先合并顶部标题区域，单独验证底部控件；连续两次新鲜识别后显示。布局根据空位选择约 190–300 宽的侧栏或 96 高的横条，没有空间就隐藏。按键提示只加快检查，不等于商店已打开。
- 部分已选记录支持可靠局 ID／英雄匹配后恢复、换局清空、证据等级、槽位替换以及手动校正与撤销。HUD 使用独立后台线程，两次稳定匹配才入库；通常每 20 秒复核，选择、等级或窗口变化可提前触发。共用图标和未确认槽位不猜测，`complete` 始终为 `false`。
- 选人提示仅在确认 Mayhem、客户端前台且客户端旁有桌面空位时出现。已有自动英雄、队友、共享池跟随与 OP.GG 资料；无空位时仍可打开面板查看。
- 出装与强化规则覆盖部分明确装备前置、任务奖励、互斥、属性转换、终极技能及暴击机制；路线显示联动收益、触发条件与构筑线索。修复目标生命值被算作自身属性联动、治疗门槛被忽略的问题；对转换量、结算顺序和部分已选保持条件说明。
- 共享池候选替换本人一格后计算指数差，显示补位收益及失去职责的代价。身份、队友、射程或伤害方向未知时不按空缺处理；射手职业覆盖不等于已确认持续输出。
- 原生方案可在自绘设置页导入查阅英雄或撤回；可选自动同步仅接受真实 Mayhem 状态及匹配英雄，至少 30 秒节流。当前身份、目标 UID、备份、二次读取、冲突和读回校验已接入，写失败或重启后保留安全撤回依据。实际验证完成，不代表局内热刷新完成。
- 已知补丁不匹配会显示警告并暂停原生方案同步；静态属性版本不匹配时停用对应属性推理。扫描超预算／连续失败会退避，相同上下文复用推荐。导出诊断只含状态、计数和耗时摘要；不导出账号、凭据、OCR 文本或画面。
- 增加后台 Start／Stop 和手动更新入口；更新使用固定 GitHub 仓库、资产摘要、冻结清单、全文件校验、独立目录、健康检查及失败恢复，选人／对局或无法核实游戏已关闭时拒绝下载安装。无自动下载或发行签名。[更新说明](UPDATES.md)

原目录离线检查为 246/264 完整三卡、773/792 正确标题，720p 为 80/88；扩展字重／亮度／背景矩阵为 394/440、1268/1320，较暗细字 720p 为 63/88。两批误认均为 0，但样本是离屏文字，拒识仍是覆盖缺口。“零误认”不等于全部识别通过；`test:replay` 使用注入数据和隐藏窗口检查异常状态流程。此前正式 ROI 和 FPS 探针返回 `NO_FOREGROUND_LEAGUE`，没有游戏帧样本，独立 ETW 启停只验证工具链。[帧时间验收](FRAME_TIME_VALIDATION.md)

## 当前结构与后续原则

以下结构已部分落地，后续继续按这些原则补齐；它们不是对竞品未公开源码的描述：

1. **把信息来源和显示方式分开。** LCU 负责选人／阶段，Live Client 负责已公开装备；Overwolf 若实验成功，只补上它实际提供的事件。OP.GG 保持统计和推荐路线来源。
2. **按局保存有证据的状态。** 已实现可靠局 ID 匹配、部分记录恢复和校正撤销；继续区分候选、重随、已选、替换与结束。重启恢复已有记录不等于恢复完整历史，只收到“最近选中”也不能推导完整构筑。
3. **有场景证据才显示。** 强化提示贴近三张卡，关闭或过期即隐藏。商店已采用独立标题与控件验证，选人提示受模式及桌面空位限制；仍需实局确认布局，不以按键、三选一或 Tab 事件代替商店显示状态。
4. **推荐给出可检查的理由。** 区分 OP.GG 档位、统计胜率和本地规则分；说明是哪件敌方装备、哪个已知强化或哪项阵容条件影响排序。
5. **保持轻量和可停用。** 不录制视频；数据变化才重算／重绘；未知或过期事件隐藏提示；对照测量后台 CPU、内存和游戏帧时间。OP.GG 官方也说明 Enhanced Overlay 在不同机器上可能更慢，不能假设 SDK 自动解决性能问题。[官方性能排查](https://help.op.gg/hc/en-us/articles/48463517332249-The-app-is-lagging-or-dropping-frames)

暂不优先加入桌宠、语音陪玩、录像、社交、全模式百科或自动选择／购买。它们不能补上本项目当前最关键的候选识别、完整状态和按场景显示，而且会增加维护与运行成本。

Overwolf 接入实验应分别记录“运行时能启动”“游戏能检测”“所需 feature 可启用”“真实候选／选择事件收到”“国服多局可用”，不把前一步的成功当成后一步的证明。其公开 LoL 字段以及当前边界见 [无截图调研](NO_CAPTURE_RESEARCH.md)。
