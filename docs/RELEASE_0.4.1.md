# Hexthon 0.4.1 · 开游戏前的开发与验证

日期：2026-11-03。基于 0.4.0，本轮完善五项可离线开发的能力；不把代码接入、模拟验证和真实对局结果混为一谈。历史 [0.4.0 记录](RELEASE_0.4.0.md) 保持不变。

## 本轮改动

1. **中文识别**：在同一小区域画面内处理低分辨率标题、断行和局部重读，仍最多 4 次 OCR，未增加整屏采集。明确的单字繁简规范化仅用于标题路径，保留原文及歧义拒识。原目录基准不变，增加独立字重／亮度／背景组合。
2. **推荐解释**：9 类明确自身属性机制、8 类暴击机制按 OP.GG ID、key 和描述核验。修复目标生命值伤害被算作自身生命装联动、治疗门槛攻击特效被当作无条件收益；增加装备路线收益、转换／触发限制及构筑线索。保留 OP.GG 路线顺序。
3. **选人比较**：对共享池候选替换本人一格后计算指数差；展示前排、射手职业、基础普攻射程与物魔方向的补位收益，以及失去现有职责的代价。本人或队友不明时不声称阵容缺位，未知射程／伤害方向不按零处理。
4. **异常回放**：生产控制器覆盖重随取消旧点击、连续选卡、迟到局 ID、断线重连、换局、进程重启、DPI／尺寸／负坐标／窗口替换／焦点变化及过期画面。修复缺失本人 ID 时 `null === null` 错删未知队友槽位的问题。
5. **交付维护**：增加后台 Start／Stop；面板手动检查、下载、校验和安装便携更新。更新采用固定 GitHub 仓库、资产摘要、冻结清单、全文件校验、侧目录、启动健康检查及失败恢复。[更新实现与边界](UPDATES.md)

## 标题覆盖情况

原基准保留 263 个目录名称、88 组三卡和既有三种分辨率，没有删减难例。

| 基准分辨率 | 完整三卡 | 正确标题 |
| --- | --- | --- |
| 1920×1080 | 83/88 | 259/264 |
| 1280×720 | 80/88 | 256/264 |
| 2560×1440 | 83/88 | 258/264 |
| 合计 | 246/264 | 773/792 |

扩展组合为 1280×720、1600×900、1920×1080、2560×1440、3440×1440，各 88 组。较暗、细字和阴影组合下的 720p 完整三卡仍只有 **63/88**。目录中规范化名称相同和纯标点名称仍保守拒识；0 次误认不能解释成全部识别成功。

最终原基准／扩展批次 OCR P95 约 **32／37 ms**，最多 4 次读取、各 1 个 OCR helper；耗时随机器负载变化。这些数据不含真实游戏采集，也不能推导 FPS 改善。复现：`npm.cmd run test:catalog` 与 `npm.cmd run test:catalog -- --variants`，报告分别为 `.qa/title-catalog/report.json` 和 `variants.json`。

## 仍需真实验证或外部来源

- **实局识别与性能**：多局卡片、商店、HUD 和选人浮层位置／关闭时机，多屏与缩放，以及相同游戏场景下暂停／启用的帧时间对照。当前不能证明“不卡顿”。
- **数据完整性**：完整敌我海克斯、可靠刷新次数、可核查胜率／样本量、转换结果和完整构筑收益仍未知；部分记录始终 `complete:false`。
- **原生商店热刷新**：0.4.0 已在腾讯客户端验证导入→读回→撤回；没有证明当前对局即时重新加载方案。
- **Overwolf**：运行时试验不等于 GEP 可用，仍缺开发凭据和腾讯国服真实候选／选择事件验证。
- **发行更新实机**：未配置代码签名，自定义发行 EXE 在本机策略下的运行尚未验证。真实 Node 回退检查不能替代发行 EXE 从下载到启动的验收；程序不会绕过 Windows App Control。
