# v0.3.1 试用前检查

日期：2026-11-03。环境为当前 Windows 主机、源码 Electron 45.2.1、腾讯客户端。全部检查在后台进行，没有激活窗口、移动鼠标或发送系统输入。测试报告存放于忽略提交的 `.qa`；可按下述命令复现。此版本没有生成新的安装包。

## 预检发现并修复的问题

- 助手启动原来强制打开识别，覆盖用户暂停。现在单独保存助手偏好，接口模式不会改掉它；暂停使在途结果失效、停止窗口监控、拒绝手动采集并释放浮层。
- 设置提交、按钮文案和实际暂停不一致。现在共用状态转换，连接／OCR／保存失败分开显示，连接恢复后清除对应旧错误。
- 校正后立刻退出可能丢掉最后记录。正常退出现在停止新变更，保存最新记录并等待队列；原子写入按顺序完成，最终 stopped 状态不会被旧 running 写入覆盖。整个退出等待预算最多约 4 秒；异常终止仍可能回退到最近完成的检查点。
- 对局 ID 先到、英雄后到时，存档恢复会错过；迟到恢复还可能复活已被新 HUD 槽位替换的手动记录。两种情况均已修复。启动尚未读完记录就退出时，也不会清除既有存档。
- 重复启动原来请求显示面板。现在只有显式 `--panel` 才请求显示；`--quit` 可让现有主实例正常退出，未取得实例锁的进程不写配置或状态。
- 启动即加载五个隐藏浮层，并同时持有全部解码图标，造成额外资源占用。现在按当前场景创建浮层、加载完成后重新核对场景，暂停／换局释放；图标逐张生成描述数据，不改变原匹配图像或阈值。

标题离线验证覆盖 9 次普通合成读数和 2 个自适应困难案例。困难名称“会心治疗”的原始 OCR 并非都成功：1920×1080 普通字重需要重读；1280×1024 换行案例整条放大仍失败，局部自适应重读后才完整识别。不能据此宣称所有 263 个标题或真实背景均已验证。

## 本机资源记录

按需浮层修改前，隐藏助手有 9 个 Electron 进程，私有内存约 820–825 MiB。修复后，隔离生命周期的多次暂停／恢复启动检查有 4 个进程，私有内存约 463–532 MiB。样本较短，受图标处理、GC、GPU 驱动和进程初始化影响；这里记录实际观察，不承诺固定降幅。

另一次正常生产入口的暂停模式采样持续 5.016 秒：4 个进程，私有内存 383.6 MiB、工作集合计 504.7 MiB；进程树 CPU 时间增加 0.203125 秒，约为单个逻辑核的 4.049%。这包含本机接口更新，窗口监控和画面采集关闭。工作集可能包含共享页，不能与私有内存混为一个指标；它也不是游戏运行时的开销或帧率测量。

原生 OCR 空白位图验证为 64×32，三次读取约 308 / 4 / 1 ms，复用一个 helper。它只证明本机 WinRT 引擎和常驻通道能运行，不代表实际中文标题 OCR 延迟。
